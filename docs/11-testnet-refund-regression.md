# Public-testnet refund regression

This is a controlled wallet experiment on Zcash public Testnet. A dedicated wallet
receives faucet test coins, creates a transparent output, shields that output,
then deliberately sends a refund to the same transparent address. A second
refund targets a fresh shielded receiver. The wallet uses Ironwood under NU7.

The experiment reproduces the public address relationship behind the refund-reuse
failure class. It does not execute Zashi CrossPay or NEAR Intents. Calling these
transactions refunds is the experiment operator's role assignment. Public bytes
alone cannot prove the relationship between the shielded notes or the identity
of their owner.

## Inspect the evidence

Open `examples/testnet-refund/vulnerable.case.json` in the workspace's file importer.
Run the case review. The high finding must be
`public-source-address-reuse-in-supplied-transactions`.

Export the signed report and its source record. The report's embedded one-off key
proves byte integrity. Use the source verifier to reproduce the findings.

Import `examples/testnet-refund/corrected.case.json` next and compare it with the
baseline report. The reuse finding disappears for the selected corrected refund.
The corrected verdict remains `insufficient`, since public bytes cannot establish
shielded delivery or certify full privacy.

The raw transaction observations include source-reported heights and compact
block hashes from `testnet.zec.rocks`. Their transaction IDs are recomputed locally.
The compact-block membership checks were performed by the capture script. They
are external source observations, not an independent consensus proof or a pinned
Veylens collector receipt. Anyone can retrieve these IDs using their own NU7
testnet node or lightwalletd and compare the bytes.

## Decoder update

Veylens supports NU6.3/NU7 v6 encoding alongside historical v4/v5. Ironwood is a
separate pool with separate commitment domains. V6 Sapling, Orchard and Ironwood
anchors bind the authorization fingerprint, rather than the effect ID. Unsupported
v6 branch IDs and reserved flag bits are rejected.

The mined faucet transaction's ID and authorization commitment were compared
against `zcash_primitives 0.31.0-pre.1`. All five experiment transactions also
match that library's fingerprints. Four synthetic codec vectors generated by the
same library cover Sapling spends and outputs, Orchard and Ironwood. The existing
ten official ZIP-244 vectors remain passing. The decoder still does not verify signatures, shielded proofs,
curve point encodings, consensus validity or ownership.

The wallet runtime was built from zingolib commit
`5d3756ffa7754917f4279ef288976584450322ae`, with the dedicated test transport
feature enabled. A local CLI change made `--waitsync` run to the chain tip when
loading an existing wallet with continuous sync settings. No wallet keys, seeds
or viewing keys belong in this repository.

## Repeat the read-only capture

Install the official lightwallet protocol Python bindings and `grpcio`, then run
`python scripts/capture-testnet.py TXID output.json`. The script expects the generated
`service_pb2` and `service_pb2_grpc` modules on `PYTHONPATH`. Generate them from
`service.proto` and `compact_formats.proto` in the official
https://github.com/zcash/lightwallet-protocol repository using `grpcio-tools`.

The fixed TLS endpoint is `testnet.zec.rocks:443`. The script checks the reported
Testnet network and NU7 branch, fetches raw bytes, and checks compact-block txid
membership when the reported transaction height is within the source tip. A
height of zero means a mempool observation. A source tip behind the transaction
height requires another capture before claiming compact-block membership.

The service sees the requested transaction ID. The script has no wallet key and
performs read-only RPC calls. Veylens checks the raw effect IDs when the returned
record is wrapped or imported as a transaction bundle.
