# Judge walkthrough

1. Open the landing page, then Open workspace.
2. Load signed API quote, then Run audit. Observe a valid provider quote
   signature, a transparent-refund configuration warning, and Insufficient
   evidence. It is a real dry quote, not a transaction.
3. Load Declared reuse example. The provider quote remains authentic but the
   shielding-source context is illustrative. The high finding explicitly says
   the source relationship is a user assertion.
4. Load Alternative route example. This edited quote is intentionally unsigned.
   The earlier source-reuse configuration is absent, but the record is not a
   verified fix and cannot produce a privacy pass.
5. Export a report. It includes addresses and record IDs; review before sharing.
6. Open Verify report and check report integrity. Expand the source check, paste
   the original input, and independently verify the digest and conclusions.
7. Edit a signed finding or evidence gap without re-signing. Integrity fails.
   Even re-signing false provenance cannot make it pass source re-analysis.

## CLI replay

```sh
npm ci
npm test
npm run build:web
node dist/src/cli.js audit test/fixtures/evidence/oneclick-live-dry-quote.json --json
# Exit 3 is expected: evidence is incomplete.
node dist/src/cli.js verify test/fixtures/evidence/REPORT_ID.signed-report.json
node dist/src/cli.js verify-input test/fixtures/evidence/oneclick-live-dry-quote.json test/fixtures/evidence/REPORT_ID.signed-report.json
```

Use the real report filename printed/generated by the audit, replacing REPORT_ID.
The dry-quote fixture signature is replayable offline. Historical deadline expiry
is displayed and does not turn the quote into live evidence.

## Claims to avoid

Do not claim a real on-chain refund was verified, that every wallet flow can be
imported, that a Unified Address proves shielding, or that a signed report proves
privacy. The demonstration authenticates provider configuration and records its
limits. Independent transaction verification remains the next milestone.

## v0.6.0 transaction inspection

Select Inspect mainnet transaction, then Run audit. Observe an ID-matched raw
v4 record, exact public outputs, and explicit gaps for confirmation and wallet
ownership. Export and re-analyse against the original evidence in Verify report.
Do not describe this historical record as a refund or a privacy leak.

Wrap node JSON before reviewing. Reuse tests exercise controlled synthetic raw
transactions whose zero proofs/signatures are not valid or mined transactions.
